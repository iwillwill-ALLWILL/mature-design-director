# Open Creative-Skill Provenance

Last live-verified: 2026-07-26.

`creative-skill-sources.json` is the single detailed record of repositories, selected `SKILL.md` paths, maintenance signals, repository-license status, absorbed behaviors, rejected assumptions, and placement. This document explains the synthesis without repeating that registry.

## What was searched

The review combined:

- media-specific GitHub repository and code searches for real `SKILL.md` files;
- recursive skill-tree inspection of official Anthropic, OpenAI, Google, GitHub, JetBrains, and established maintainer repositories;
- presentation, image, infographic, diagram, video, 3D, game, and music-focused community repositories;
- awesome indexes for discovery only, followed by checks against the primary repository;
- the actual content and license boundary of shortlisted skills.

GitHub changes continuously, so “all” means all mature/high-signal sources found through the documented live search—not a false claim that every future or unindexed repository is known.

## Primary influences

- **Anthropic:** authored aesthetic thesis, brand constraints, progressive references, editable source plus rendered proof.
- **OpenAI:** design-system/generation/implementation separation, exact-state screenshots, image and format mechanics as delegated execution.
- **Google Stitch:** semantic taste axes, design-system round trips, code-to-design recovery, design intent that survives tool boundaries.
- **GitHub Awesome Copilot:** anti-generic diagnostics, concrete rendered review, editable diagram/vector/3D sources, screenshot evidence.
- **Addy Osmani:** interface architecture, accessibility, responsiveness, performance, and explicit engineering contracts.
- **Baoyu Skills:** information-structure-first visual explanation, persistent prompts/reference roles, reproducible batched rendering, source-to-output separation.
- **JetBrains:** cross-agent compatibility and upstream deduplication rather than a new design authority.
- **Office-focused skills:** content extraction → narrative → visual production → package mechanics separation and reverse export checks.
- **Music-focused skills:** release identity across sound and image, rights/provenance, stems/source preservation, sequence-level listening review.
- **D3 and image-reference libraries:** encoding-before-styling, accessible data alternatives, dynamic manifests, and preview-before-selection.

## What was deliberately not absorbed

Maturity does not make every rule universal. The synthesis rejects:

- hardcoded house taste such as one font ban, one accent count, one radius, one density, or perpetual motion;
- fashionable component/effect catalogs acting as art direction;
- provider-specific tools becoming mandatory architecture;
- image-backed slides replacing native editable delivery by default;
- programmatic canvas/vector primitives standing in for authored visual media;
- bulk installation of discovery indexes;
- copied prose or assets when repository/file licensing is unclear;
- redundant aggregator copies being treated as independent evidence.

## Original synthesis

Upstream skills usually own one tool or output. This project adds the missing vertical coordination:

1. one final-user creative authority;
2. a seven-stage intent → foundation → direction → proof → production → critique → learning flow;
3. declarative capability contracts selected by outputs rather than top-level specialist competition;
4. mature skills and production projects as governed evidence maps, not dependencies;
5. delegated mechanics with no aesthetic veto;
6. capability-specific proof requirements and whole-artifact review;
7. authorized, sanitized learning promoted to the narrowest layer.

## Import discipline

For a new source:

1. read the primary `SKILL.md` and current license boundary;
2. name the exact behavior that would change;
3. compare it with the capability registry;
4. test the behavior on a representative artifact;
5. patch the narrowest capability, or the constitution only for a cross-capability invariant;
6. add a capability only for a recurring output class that no existing contract can own;
7. keep tool-specific commands in an adapter or external mechanics skill;
8. record rejected assumptions as carefully as absorbed behavior.
